HOW A RIDE MOVES THROUGH THE SYSTEM

Request to receipt in three handoffs.

Every trip passes through the same three services in sequence — each one doing exactly one job, so a spike in ride requests never slows down payments.

01

Rider requests a trip

The Ride Service takes the pickup and drop-off, authenticates the session with a JWT, and opens a booking record.

02

Driver Service finds a match

Nearby available drivers are ranked by distance and ETA, one is assigned, and both apps get a live status push.

03

Payment Service settles the fare

On trip completion, the fare is calculated and charged automatically, and a receipt is issued to the rider.

UNDER THE HOOD

An architecture built to isolate failure.

Ride dispatch, driver management, and payments run as separate services, so a slowdown in one never takes the others down with it. Everything is discovered and routed dynamically — nothing is hard-wired.

WHAT EACH SERVICE HANDLES

Built for the moments that can't wait.

RIDE SERVICE

Booking and live status

Creates and tracks every trip from request through drop-off, and broadcasts status changes to both rider and driver in real time.

DRIVER SERVICE

Fleet and matching

Keeps a live map of driver location and availability, and runs the matching logic that assigns the closest suitable driver to each request.

PAYMENT SERVICE

Secure fare settlement

Calculates the final fare, processes the charge, and issues a receipt — isolated from ride logic so a payment hiccup never strands a trip in progress.

AUTH SERVICE

JWT-secured sessions

Issues and verifies tokens across every service call, so no request reaches Ride, Driver, or Payment without a valid, signed session.

RELIABILITY AT RUSH HOUR

Built to stay up when the city gets busy.

Eureka-based service discovery

Every instance registers itself on startup, so the network always knows which services are healthy and reachable.

Client-side load balancing

Requests spread automatically across every healthy instance of a service, so no single node becomes a bottleneck.

One gateway, one front door

All traffic is routed through a single API Gateway, keeping authentication and rate limits consistent across the whole network.
